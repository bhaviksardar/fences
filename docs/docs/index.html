Documentation

Put fences around your agents.

Fences is on-call for AI agents. It shows every run live, records what the agent decided and why, lets you stop any run in one click, and enforces limits on spend, steps, time and tokens that the agent can't raise itself.

The SDKagentfences on PyPI and npm, for Python and TypeScript. One decorator on your agent function, one checkpoint() call after each model call, and guards on the tools that matter.
The dashboardLive runs, the decision trail behind each one, and limits you can raise mid-run to let a stopped agent continue.

You can run the SDK entirely on its own (local mode: no account, nothing leaves your process) or connect it to Fences Cloud (cloud mode, coming soon) with an API key. Your agent code is the same either way; only init() changes.

Two minutes

Quickstart

This runs fully locally. No account, no API key, no backend.

  1. Install the SDK

    Requires Python 3.9 or newer.

    pip install agentfences

  2. Fence an agent

    Wrap the agent function with @governed and its limits, then call checkpoint() after each step with what that step cost.

    import asyncio
import agentfences
from agentfences import governed, checkpoint, log_decision

agentfences.init(local_only=True)

@governed(budget_usd=0.10, max_iterations=20)
async def my_agent(query: str) -> str:
    for step in range(100):                       # a loop that would run away
        log_decision(reasoning=f"step {step}: searching", action="search")

        result = await checkpoint(cost_delta_usd=0.02, tokens_used=200)
        if result.breached:
            return result.message
    return "done"

print(asyncio.run(my_agent("hello")))

  3. Run it

    Five steps spend exactly $0.10, which is allowed. The sixth would take it to $0.12, so the agent stops and returns:

    I've reached my budget limit (spent $0.1200 of $0.1000). I'll summarize what I found so far.

    Nothing threw an exception. The agent read the result and decided how to stop, which is the default behaviour. See Handling a breach for the other options.

Cloud mode

Connect to the dashboard

Connecting sends every run, checkpoint and decision to this backend, so you can watch them live and change limits while they run.

  1. Create an account and an API key

    Sign up, then open Dashboard → API keys and create a key. The full key (fc_…) is shown only once, so copy it straight away. Fences stores only a hash of it.

  2. Point the SDK at this backend

    Replace the local_only line with your key and this site's address. Keep the key in an environment variable rather than in code.

    import os
import agentfences

agentfences.init(
    api_key=os.environ["FENCES_API_KEY"],
    endpoint="https://your-fences-host",
)
    Always pass endpoint. It defaults to http://localhost:8000, which isn't a Fences server, so without it the SDK can't reach Fences and only enforces limits locally.

  3. Run your agent

    The run shows up in the dashboard as soon as it starts, and its spend, steps and decisions update live on every checkpoint.

Guide

Limits

Set any combination on @governed. They are checked at every checkpoint(); the first one exceeded stops the run.

LimitParameterIf not set anywherebreach_type
Spend (USD)budget_usdno budget: spend isn't capped, and Fences flags itbudget_exceeded
Stepsmax_iterations100iteration_limit
Wall-clock time (ms)max_duration_ms300_000 (5 min)time_limit
Tokens (input + output)max_tokens0 = no limittoken_limit

How limits are counted

  • A limit trips only once it is exceeded. budget_usd=0.10 lets the run spend exactly $0.10, and max_iterations=5 allows five full checkpoints; the sixth trips.
  • One iteration = one checkpoint() call. Call it once per model call (or once per loop turn) so the count means something.
  • Each checkpoint reports one step. Pass that step's model response, or its cost_delta_usd and tokens_used, never running totals. Fences adds them up.
  • Limits are checked at checkpoints, not in between. Fences never interrupts a model call that is already running. A run with a 5-minute limit that makes one 10-minute call finds out at the next checkpoint.
  • If several limits are exceeded at once, the order is spend, then steps, then time, then tokens.

You don't need to know what a call costs: pass the response and Fences prices it. See Cost tracking.

Guide

Cost tracking

Pass the model's response to checkpoint() and Fences works out what the call cost. It reads the model name and token usage, including cache reads and writes and reasoning tokens, and prices them from a built-in table of current list prices. You never look up a price.

response = client.chat.completions.create(model="gpt-4o", messages=messages)
result = await checkpoint(response)
print(result.spent_usd)   # the run's total so far
  • Supported responses: OpenAI (Chat Completions and Responses), Anthropic, Gemini and LangChain messages, or any object or dict with the same usage fields. If a gateway such as OpenRouter reports the billed cost, that is used instead.
  • Built-in prices: about 290 models from OpenAI, Anthropic, Google, Mistral, DeepSeek, xAI and Groq, including long-context pricing, from LiteLLM's price list. They're refreshed with each release.
  • Other models: a model missing from the table still has its tokens counted, and Fences logs a warning once, because budget_usd can't stop a model it can't price. Add prices in USD per 1M tokens: agentfences.init(..., prices={"my-finetune": {"input": 2.0, "output": 6.0}}).
  • Extra costs: add a paid tool call or anything else to the step with checkpoint(response, cost_delta_usd=0.01). Without a response, cost_delta_usd and tokens_used are the step's whole cost and tokens.
  • Streaming: pass the final message, or the last chunk once it carries usage (OpenAI: stream_options={"include_usage": True}).
  • Prices are standard list prices: batch, priority and flex discounts aren't applied.
  • Checked before the call: with instrument=True or a framework integration, each model call is also checked against the budget before it's sent, and refused with FencesStop if its worst case could overspend. See Frameworks.
  • A cost that isn't a finite number of zero or more (NaN, negative, a string) raises instead of being counted, since it would switch the budget off. Decimal amounts are fine. 0.8

Guide

Handling a breach

By default checkpoint() never raises. It returns a CheckpointResult that your agent reads, so it can stop cleanly instead of crashing halfway through a task.

result = await checkpoint(response)

result.ok             # True while within every limit
result.breached       # True once a limit is exceeded
result.breach_type    # "budget_exceeded" | "iteration_limit" | "time_limit" | "token_limit"
result.message        # first-person text you can return to the user
result.system_prompt  # instruction you can give the model so it wraps up

Option 1: return a message

The simplest exit. result.message reads like the agent speaking, for example “I've reached my iteration limit (21 steps). I'll summarize what I found so far.”

Option 2: let the model summarise

Add result.system_prompt to the conversation and make one last call. The model stops working and tells the user what it found and why it stopped.

if result.breached:
    messages.append({"role": "system", "content": result.system_prompt})
    return call_llm(messages)   # this final call isn't counted; there is no checkpoint after it

What happens to the run

The run is marked breached the moment a limit trips. Further checkpoints in that run keep returning the breach, unless someone raises the limit in the dashboard (see Raise limits and resume). When the function returns, the run ends with status breached, success or error (an exception other than a Fences one was raised).

Guide

Real LLM loops

The pattern is always the same: call the model, report that call's cost and tokens, check the result. These examples use the OpenAI and Anthropic Python clients; any provider works, since Fences only sees the numbers you pass.

OpenAI-style chat completions

from openai import AsyncOpenAI
from agentfences import governed, checkpoint, log_decision

client = AsyncOpenAI()

@governed(budget_usd=1.00, max_iterations=25, max_tokens=200_000)
async def research(question: str) -> str:
    messages = [{"role": "user", "content": question}]
    while True:
        log_decision(reasoning="asking the model for the next step", action="llm_call")
        resp = await client.chat.completions.create(model=MODEL, messages=messages, tools=TOOLS)
        result = await checkpoint(resp)   # Fences reads the usage and prices the call
        if result.breached:
            messages.append({"role": "system", "content": result.system_prompt})
            final = await client.chat.completions.create(model=MODEL, messages=messages)
            return final.choices[0].message.content

        msg = resp.choices[0].message
        if not msg.tool_calls:
            return msg.content
        messages += [msg, *await run_tools(msg.tool_calls)]

Anthropic messages

The same loop. Pass the response as it is; Fences reads Anthropic's usage, including cache reads and writes.

resp = await client.messages.create(model=MODEL, max_tokens=1024, messages=messages, tools=TOOLS)
result = await checkpoint(resp)

MODEL, TOOLS and run_tools are yours.

Guide

Sync, streaming & concurrent agents

Synchronous agents

@governed works on plain functions too. Use checkpoint_sync() inside them: same arguments, same result.

from agentfences import governed, checkpoint_sync

@governed(budget_usd=0.25)
def classify(ticket: str) -> str:
    resp = llm.invoke(ticket)
    result = checkpoint_sync(resp)
    return result.message if result.breached else resp

Streaming agents

Decorate an async generator and the whole stream is one run. If the caller stops reading early, the run still ends cleanly.

@governed(budget_usd=0.50, max_iterations=10)
async def stream_answer(question: str):
    async for chunk, cost, tokens in my_streaming_loop(question):
        yield chunk
        if (await checkpoint(cost_delta_usd=cost, tokens_used=tokens)).breached:
            return

Concurrent and nested runs

Every call to a @governed function is its own run with its own limits, even when many run at once in the same event loop:

answers = await asyncio.gather(*(research(q) for q in questions))   # one run per question

If one governed function calls another, the inner call is a separate run. While it runs, checkpoints count against the inner run; when it returns, checkpoints count against the outer run again.

Guide

Decision trail

Call log_decision() before each step to record why the agent is doing it. The trail is most useful on runs that went wrong. It is kept for breached and failed runs too, and shows up in the dashboard under each run.

log_decision(
    reasoning="Search returned nothing; retrying with a narrower query",   # 1–2,000 characters
    action="retry_search",                                                  # optional short label, up to 200
)
  • Each decision is tagged with the iteration it happened in.
  • It never slows the agent down: decisions are sent from a background thread, in order.
  • Queued decisions are flushed automatically when the process exits. In serverless functions, which can be frozen before that happens, call agentfences.flush() at the end of the handler.
  • Outside a @governed function, log_decision() does nothing.

Raise limits and resume

Open a running or breached run and edit its limits. If the run was breached and the new limits cover what it has used, it goes back to running. The agent's next checkpoint() then passes, and the agent carries on where it was.

This only helps an agent that is still calling checkpoint() after a breach, for example one that waits or retries instead of returning straight away. Runs that already ended can't be changed.

Only a logged-in dashboard user can raise limits. The API key your agent holds can't, so an agent can never unfence itself.

Key governance

The limits in @governed(...) live in the agent's own code, so on their own they can't stop an agent that asks for more. Add each agent on the dashboard's Agent limits page (Add agent): it gets its own API key that only it can use, and that key carries the agent's rules, changeable only there:

  • Per-run ceilings (max spend, steps, minutes and tokens): every run started with the key is capped at them, whatever it asks for. /api/runs/start returns the limits the run actually got.
  • Daily and monthly spend caps across all of the key's runs (UTC), so ending a run and starting a fresh one doesn't reset anything. Crossing one fences the run with key_daily_budget or key_monthly_budget.
  • One agent name: runs started with the key always carry it, so an agent can't report as another.

A key also only sees the runs it started. The dashboard sees every run in your account.

Stop a run

Open a running run and press Stop run. Its next checkpoint() returns breached with breach_type stopped_by_user, so the agent winds down like any other breach. Raising its limits resumes it.

Deleting data

From the dashboard you can delete a single run, every run of an agent, or your whole account (runs, audit trails, keys and login). Deletion needs a dashboard login too, so an agent can't erase its own audit trail.

Guide

Frameworks

Agents built on a framework need no decorators: each model call is checked against the budget before it's sent, then recorded with its tokens and cost and checkpointed, so limits apply, and each tool call is recorded. Limits work as in @governed and are all optional. Callbacks can't hand a result back to the agent, so when a limit is crossed these raise FencesStop, which carries the usual breach_type, message and system_prompt.

LangChain and LangGraph

from agentfences import FencesStop
from agentfences.langchain import FencesCallbackHandler

try:
    graph.invoke(inputs, config={"callbacks": [FencesCallbackHandler(budget_usd=2)]})
except FencesStop as stop:
    answer = stop.message

The outermost run becomes a Fences run (or joins one already started by @governed). Sync and async graphs both work, and on_breach="hold" can be passed as in @governed.

OpenAI Agents SDK

from agentfences import FencesStop, openai_agents

try:
    result = await openai_agents.run(agent, "Research cats", budget_usd=2)   # Runner.run, governed
except FencesStop as stop:
    answer = stop.message

Already inside @governed? Pass hooks=openai_agents.FencesRunHooks() to Runner.run. Needs Python 3.10+.

Any OpenAI or Anthropic call

agentfences.init(api_key=..., endpoint=..., instrument=True)

Records every OpenAI and Anthropic call made inside a governed run (model, tokens, cost, latency, and the error and status code if it failed) with no other code changes. In a run with a budget, each call is first checked: its worst case (the request's input, estimated high, plus its output cap) must fit what's left, or it raises FencesStop (budget_exceeded) and never reaches the provider. Each call's worst case is held while it's in flight, so parallel calls can't overspend together.

Without max_tokens, the worst case uses the model's whole output limit (16,384 tokens for gpt-4o), so set max_tokens on calls in runs with small budgets.

Calls are recorded, not counted as steps: keep calling checkpoint(response) where limits should be checked. Don't combine it with a framework integration, or calls are recorded twice.

Guide

Guarded tools 0.4

A checkpoint runs after a step, so on its own it notices a limit once it's crossed. For actions with consequences (refunds, payments, writes to production), guard the tool, and it asks Fences before it runs:

@agentfences.tool(cost_usd=lambda order_id, amount: amount, approve=True)
def issue_refund(order_id: str, amount: float): ...

@agentfences.tool(guard=True, timeout_s=30)
async def deploy(service: str): ...
  • The tool runs only if its run isn't stopped, paused, over a limit or quarantined. Otherwise it raises ToolBlocked (with reason and breach_type) and its code never runs. The model can't talk its way past this: the check sits in the tool itself.
  • cost_usd (a number, or a function of the tool's arguments) is reserved before the call and charged after, so five parallel $40 refunds against a $100 budget can't all go through: two do. A call that raises is released uncharged; one that times out is charged, because it may have happened.
  • approve=True asks a person on the dashboard before each call. The dashboard can also require approval for a tool, and the SDK then asks for it.
  • Guards fail closed: if Fences can't be reached, the tool is blocked. In local mode the SDK applies the same rules itself, and approve=True is always denied, as there's no one to ask.
  • timeout_s works on any tool, guarded or not: past it, the call raises TimeoutError.

What each part guarantees, and what it can't, is in ENFORCEMENT.md.

Guide

MCP tools 0.7

Wrap an MCP client session and every tool call it makes is recorded, with no decorator per tool. The tools you name are guarded as above:

session = agentfences.mcp.wrap(session, guard=["send_email"], cost_usd={"refund": lambda args: args["amount"]})

guard=True guards every tool, and approve=[...] names tools a person approves first. A result with isError is recorded as a failed call and still comes back to the agent. In TypeScript: mcp.wrap(client, { guard: [...], costUsd: {...} }).

TypeScript

The same SDK for Node 18+, with no dependencies: npm install agentfences. It follows the same protocol, limits, breach types, messages and price table as the Python SDK.

import { init, governed, checkpoint, tool, context } from "agentfences";

init({ localOnly: true });

const research = governed(async (question: string) => {
  const response = await openai.chat.completions.create({ model: "gpt-4o", messages });
  const result = await checkpoint(response);      // priced from its usage
  if (result.breached) return result.message;
}, { budgetUsd: 0.5, maxIterations: 20 });

checkpoint() also prices Vercel AI SDK results (generateText), Gemini and LangChain.js. tool() (with guards, costs, approvals and timeouts), context(), logDecision(), live control, containment hooks, onBreach: "hold", mcp.wrap, redaction and error capture work as in Python.

Model calls 0.8: instrument(client) records every OpenAI and Anthropic call and checks it against the budget before it's sent, as instrument=True does in Python:

import OpenAI from "openai";
import { instrument } from "agentfences";

const openai = instrument(new OpenAI());   // one call covers every client of that SDK

The SDK's own promise comes back, with .withResponse() and .asResponse(); a refused call rejects with FencesStop. JavaScript can't stop running code, so a run stuck after a stop has its governed call reject with FencesStop and run.signal abort: pass the signal to fetch so the work really stops. Not in the TypeScript SDK yet: the LangGraph and OpenAI Agents integrations.

On-call

Live control & evidence

What on-call needs while an agent is running: what it's calling, a way to hold it, and a way for it to ask before doing something risky. Older SDKs keep working; they just don't get these.

Tag runs with context

agentfences.init(api_key="fc_...", endpoint="...", environment="prod", release="v1.4.2")

with agentfences.context(user_id="u_123", session_id="s_9"):
    await support_agent(question)

Tags show on each run in the dashboard, and the run search matches them.

Record tool and model calls

@agentfences.tool
def web_search(query: str) -> list: ...

Each call is recorded with its argument names, how long it took, and the error if it failed. Argument values stay in your process unless you pass init(tool_arguments="full") 0.9; a guarded tool's check and an approval request still send them, since rules and approvers need them. Model calls priced by checkpoint(response) are recorded with their tokens and cost. They appear under Tool and model calls on the run.

Pause, resume and stop

On a running run, Pause holds the agent at its next checkpoint until you press Resume (after pause_timeout_s, an hour by default, it stops with breach paused). Stop run reaches the agent within seconds, between checkpoints. The run shows when it was last heard from; one that goes quiet may be stuck.

A stuck run is halted. 0.4 If a run doesn't reach a checkpoint within stop_grace_s (30 seconds by default) of a stop, because it's stuck in a tool say, the governed call raises FencesStop. An async run is cancelled. A sync run 0.8 has FencesStop raised in its thread: at once in Python code, or when a blocking call it's in returns (CPython). A streaming run is cancelled only while its own code runs. init(stop_grace_s=None) turns this off.

Containment hooks 0.5

def revoke(event):   # {"type", "run_id", "agent_name", "id", "by", "reason"}
    vault.revoke(token_for(event["run_id"]))

agentfences.init(api_key=..., endpoint=..., on_stop=revoke, on_quarantine=revoke)

They run in your process when a stop or quarantine arrives, to contain what Fences can't reach, such as a credential the agent holds. on_stop runs once per run, on_quarantine once per quarantine. Whether each worked, failed or timed out (30 seconds) is reported to Fences. The SDK also acknowledges every dashboard command, so the dashboard can tell "the agent has it" from "the agent hasn't acknowledged".

Wait at a limit 0.6

@governed(budget_usd=5, on_breach="hold")   # or init(on_breach="hold") for every agent
async def nightly_report(): ...

Instead of ending, a run that crosses a limit waits at its checkpoint, shown as held on the dashboard, until someone raises the limit and resumes it, and then carries on. A model call or guarded tool refused for budget waits the same way. A stop ends the wait; after pause_timeout_s the breach is returned as usual. Cloud mode only. Use it for background agents: a held agent holds its thread.

Quarantine an agent

Quarantine on the agent's card pauses its running runs and refuses new ones: the governed call raises AgentQuarantined before any agent code runs. Release undoes both.

Ask before acting

approval = await agentfences.request_approval("Refund $240 to order 1182?", amount_usd=240)
if not approval.granted:
    return f"I didn't issue the refund: {approval.note}"

The request appears at the top of Runs with Approve and Deny. An approved amount is added to the run's budget. The agent waits up to timeout_s (10 minutes by default) and is told "denied" if no one answers, or at once if the server refuses the request; it never hangs or raises.

Agents with no budget

Leaving budget_usd out of the code and the dashboard is allowed, never silent: the agent's logs get a warning with a link, its runs carry a No budget badge, and on its first such run the dashboard asks you to Set a budget or Keep unlimited. Daily and monthly caps still apply.

Guide

Reliability

If the backend can't be reached

Each call to the backend times out after 3 seconds. If a call fails, the SDK logs one warning per run and enforces the same limits locally, with the numbers it last had, so an outage never leaves an agent unfenced and never stops a healthy one. Guarded tools are the exception: they fail closed.

If you'd rather stop agents when Fences can't be reached, fail closed:

agentfences.init(api_key=..., endpoint=..., fail_closed=True)
# an unreachable backend now counts as a breach (breach_type "fences_unreachable")

The backend is the source of truth

In cloud mode the backend decides whether a checkpoint passes, and the SDK adopts its totals. That catches spend the local process can't see, such as another worker reporting against the same run, and picks up limits raised in the dashboard.

Rejected keys fail loudly

A wrong API key is not treated as an outage. When a run starts, the SDK raises FencesAuthError (a PermissionError) before any agent code runs, so you notice immediately. A key revoked during a run ends it at its next checkpoint with fences_unreachable and blocks its guarded tools; nothing is raised over the agent's own result. 0.8

No blocking

In async agents, backend calls run in a worker thread so they never block the event loop. Decisions and tool and model call records are sent in the background and flushed at exit; call agentfences.flush() before a serverless handler returns.

Guarantees

What Fences guarantees at each level (budgets and checkpoints, live control, guarded tools), and what it can't, each with the test that proves it: ENFORCEMENT.md.

Python SDK

Everything is importable from agentfences. The latest release is on PyPI.

init(api_key=None, endpoint="http://localhost:8000", local_only=False, fail_closed=False, prices=None, environment=None, release=None, redact=None, instrument=False, heartbeat_s=15.0, pause_timeout_s=3600.0, stop_grace_s=30.0, on_stop=None, on_quarantine=None, on_breach=None, tool_arguments="names")

Call once at startup, before any governed function runs. Pass either local_only=True, or an api_key and endpoint. Calling a governed function before init() raises RuntimeError. prices adds or overrides model prices in USD per 1M tokens, input and output both required (see Cost tracking); environment and release tag every run; redact can change or drop anything before it leaves your process; instrument=True records and prechecks OpenAI and Anthropic calls (see Frameworks). tool_arguments is what a recorded tool call carries of its arguments: "names" (the default), "full" or "none". heartbeat_s, pause_timeout_s, stop_grace_s, on_stop, on_quarantine and on_breach tune live control.

@governed(budget_usd=None, max_iterations=None, max_duration_ms=None, max_tokens=None, on_breach=None)

Makes each call of the decorated function a run. Every limit is optional: one left out comes from the agent's limits on the dashboard, then the defaults in Limits. A bare @governed() works. Works on async and sync functions and async generators. The run is reported under the agent its key belongs to. on_breach="hold" makes it wait at a limit.

await checkpoint(response=None, cost_delta_usd=0.0, tokens_used=0) → CheckpointResult

Records one step, counts one iteration, and checks every limit. Pass the model's response and Fences prices it; cost_delta_usd and tokens_used add extra amounts, or are the whole step without a response. Outside a governed function it does nothing and returns an OK result. Never raises for a breach.

checkpoint_sync(response=None, cost_delta_usd=0.0, tokens_used=0) → CheckpointResult

The same, for synchronous code.

@tool(name=None, timeout_s=None, guard=False, cost_usd=None, approve=False)

Records each call of an agent tool; with guard, cost_usd or approve it's checked with Fences before it runs. See Guarded tools.

await request_approval(reason, amount_usd=None, timeout_s=600) → Approval

Asks a person on the dashboard and waits for the answer (granted, by, note, amount_usd). request_approval_sync for synchronous code.

mcp.wrap(session, guard=(), cost_usd=None, approve=())

Records, and optionally guards, every tool call an MCP client session makes. See MCP tools.

log_decision(reasoning, action=None)

Adds an entry to the run's decision trail. See Decision trail.

flush(timeout=5.0)

Waits up to timeout seconds for queued decisions and call records to reach the backend, and for on_stop and on_quarantine hooks to finish. Runs automatically at exit.

get_active_run() → RunState | None

The current run, if any. Useful for reading run_id, cost_usd, iterations, tokens_used and duration_ms from inside the agent.

REST API

Not using Python or TypeScript? A fenced run is four HTTP calls (start, checkpoint, decisions, end), so any language can be fenced; the rest add live control and guarded tools. Send your key in the X-API-Key header and JSON bodies. The full contract, including what each status code means to the SDK, is PROTOCOL.md.

EndpointBodyReturns
POST /api/runs/startrun_id (you choose, unique), agent_name; optional limits (null = take the dashboard's) and context (string → string, up to 32 keys){"ok": true, "limits": {...}, "notices": [...]}: the run's effective limits; 409 if the run_id exists; 423 if the agent is quarantined
POST /api/runs/{id}/checkpointcost_delta_usd and tokens_used for this step. The server counts steps and measures time itself (iterations and duration_ms are accepted but ignored)See below. On a fenced run: {"ok": false, "breach": ...} again, with the reason; 409 if the run has ended
POST /api/runs/{id}/decisionsiteration, reasoning, optional action{"ok": true}
POST /api/runs/{id}/endstatus (success, error or breached), optional breach (for a breach the SDK decided, such as a refused model call), error and exception (type, message, stack){"ok": true}. A breached run stays breached
POST /api/runs/{id}/spans{"spans": [...]}: tool calls, model calls and approvals, shaped like OpenTelemetry GenAI spans{"ok": true}
POST /api/heartbeat{"runs": [{"run_id", "iterations", "spent_usd", "tokens_used", "paused", "stopped", "held"}], "acks": [...]} for the process's live runs, acknowledging the commands it got (and how its hooks went){"commands": [...]}, each with an id: stop, pause, resume, quarantine, limits, approval (checkpoint replies carry them too)
POST /api/runs/{id}/guardphase: "check" with guard_id (you choose), tool, arguments, amount_usd, approval_id; then phase: "settle" with guard_id, outcome (ok, error, unknown) and cost_usdCheck: {"allow": true}, with the amount reserved, or {"allow": false, "reason", "breach"}, or needs_approval. Settle: {"ok": true}
POST /api/runs/{id}/approvalsapproval_id (you choose), reason, optional amount_usd{"ok": true}; the answer arrives as an approval command
GET /api/runs{"runs": [...]}, newest first
GET /api/runs/{id}{"run": {...}}
GET /api/runs/{id}/decisions{"decisions": [...]}, oldest first

A full run with curl

BASE=https://your-fences-host
KEY=fc_...

curl -X POST $BASE/api/runs/start -H "X-API-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"run_id": "run-123", "agent_name": "support_bot", "budget_usd": 0.50, "max_iterations": 20}'

curl -X POST $BASE/api/runs/run-123/checkpoint -H "X-API-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"cost_delta_usd": 0.02, "tokens_used": 450, "iterations": 1, "duration_ms": 1200}'

curl -X POST $BASE/api/runs/run-123/end -H "X-API-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"status": "success"}'

Checkpoint responses

// Within limits
{ "ok": true, "spent_usd": 0.02, "iterations": 1, "tokens_used": 450 }

// Breached: stop the agent. Totals and current limits are included.
{ "ok": false, "breach": "budget_exceeded",
  "spent_usd": 0.52, "budget_usd": 0.5, "iterations": 14, "max_iterations": 20,
  "tokens_used": 6300, "max_tokens": 0, "duration_ms": 18200, "max_duration_ms": 300000 }

The server adds up cost_delta_usd and tokens_used itself, so send each step's amounts, not totals. Concurrent checkpoints on one run are counted exactly.

Errors

CodeMeaning
401Missing, wrong or revoked API key
404No such run, or it belongs to another account
409Duplicate run_id, checkpoint on a run that isn't running, or limits changed on a finished run
422Invalid body, e.g. a missing field or a negative cost. The response says which field

Live WebSocket

The dashboard's live view is a WebSocket you can use too, for example to pipe breaches into Slack or your own monitoring.

wss://your-fences-host/ws/runs?api_key=fc_...

On connect you get initial_state with your 50 most recent runs, then one JSON message per event. Every message except ping includes the full run.

typeSent when
run_startedA run starts
checkpointA checkpoint passes
run_breachedA limit trips; includes breach
limits_updatedLimits change; includes changes
run_endedA run ends
pingEvery 30 seconds, to keep the connection open

A bad key closes the socket with code 4001.

Troubleshooting

RuntimeError: Call agentfences.init() before using Fences

A governed function ran before init(). Call it once at startup, at module level or in your app's startup hook.

FencesAuthError: Fences API key rejected

The key is wrong or was revoked. Check the FENCES_API_KEY your process actually sees, or create a new key in the dashboard. (Before 0.8 this was a plain PermissionError; FencesAuthError is one, so except PermissionError still works.)

FencesStop: I can't make another model call without risking going over my budget

The budget precheck refused a model call whose worst case could take the run over budget. Set max_tokens on the call, which lowers its worst case, or raise the budget. The log line says how much was left.

ToolBlocked: Fences blocked …

A guarded tool wasn't allowed: its reason says why (stopped, over budget, not approved, quarantined, or Fences couldn't be reached, as guards fail closed).

“Fences backend unreachable … enforcing limits locally” warning

The SDK couldn't reach endpoint. Check the address (it must be your Fences Cloud address, not the localhost default) and that the machine can reach it. Your limits are still enforced in the meantime.

My runs don't appear in the dashboard

Either the SDK is in local mode (local_only=True), or the key belongs to a different account from the one you're logged into.

The agent stopped one step later than I expected

Limits trip once exceeded, not when reached: max_iterations=5 allows five checkpoints.

The time limit didn't stop a long model call

Limits are checked at checkpoints, so a single call that runs past the limit is caught at the next checkpoint(). Set a timeout on the model call itself if you need a hard cut-off.
